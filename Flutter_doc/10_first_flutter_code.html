4. Stateful Widget - -

- State can changed.
- when we want to changes at run time,without restarting your application
- Data can change externally.
- Gets rendered when input data or local state changes.
- It is not a single class. It is a combination of two class. E.g: If my class name is : MyApp then other class is :  MyAppState
      class MyApp extends StatefulWidget {  }
	  class MyAppState extends State { }

- MyApp - This class can be recreated when external data changes
- MyAppState - This class never recreated.It is used for storing our state.
             - It contains the build method.
- State<>  - It is a generic class 
- State -- It tells that State class belnogs to MyApp class.
- State - State class belongs to StatefulWidget class.
- createState() - This method need to be overwritten. So overwrite used.
- setState() - It updates the method by calling the build method.
               Build method is called when u calling setState method.
- extends --> It means inheritance. MyApp inherited the feature of statelesswidget class.

Folder structure details -

android - Flutter project contain .Android platform specific setting,resources and code.
build - contains the output generated when you build or run the flutter project.
      - You will find all the release related files/folder like apks and app bundles here.
	  
ios - ios platform specific setting resources and codes.
lib - library folder. all pages will  be create here.
test - any testing related code, you write. If you want to write any test cases, like app need this much memory, disk space, performance.

.gitignore - unnecessary files will be ignored, not to push in git.
.metadata - flutter related metadata
.packages -
            pre installed packages
			User defined packages
			
pubspec.yaml - contain flutter app specific metadata configuration.
             - You can configure dependencies such as external packages , images assets, font files, app versions etc with the help of this file. 
			 
pubspec.lock - it is a helper file created next to pubspec.yaml file . It lists the specific versions of each dependencies that packages use in your app and ensure the version stays consistent across different developer machine. no need to make any changes here.
